# 魔法存储合成检查

在仓库根目录先编译模组，再执行（包路径替换为实际安装版本）：

```powershell
dotnet build ComprehensiveStatistics.csproj -p:BuildMod=false -p:TargetFramework=net8.0 --no-restore
dotnet run --project Tests/MagicStorageChecks/MagicStorageChecks.csproj -p:TmlPath=D:/Steam/steamapps/common/tModLoader -- D:/Steam/steamapps/common/tModLoader D:/Steam/steamapps/workshop/content/1281930/2563309347/2025.7/MagicStorage.tmod D:/Steam/steamapps/workshop/content/1281930/2908170107/2025.6/SerousCommonLib.tmod bin/Debug/net8.0/ComprehensiveStatistics.dll
```

检查器只读打开真实模组包，使用原生 TmodFile 提取程序集及对应合成源码到忽略的 `obj/MagicStorageAudit`；不启动游戏，不读取或修改人物世界存档。先预编译真实入口、递归计算和编译器闭包，再安装并释放生产 Hook 和唯一材料接受 IL 边界。`MAGIC_STORAGE_ACTUAL_HOOKS_OK` / `MAGIC_STORAGE_RECURSIVE_HOOKS_OK` 分别表示普通、递归入口实际安装验证通过。

隔离夹具使用生产适配器、真实 MonoMod Hook、与上游一致的闭包及提取回退布局；以模拟配方回调替代游戏回调，根入口使用生产 ExecuteCraft 事务，不读取 Main 玩家状态。覆盖普通和批量、批量回退到逐件、回调改数量、重复通知、存储满余量、零材料、压缩合并、材料不足回退、模拟排除、递归排除、非单人门控、无关回调、错误结算身份、异常及世界切换失效。夹具按优化 IL 编译以匹配实际上游发行包布局。`MAGIC_STORAGE_SCENARIOS_OK` 不代表真实库存、掉落和游戏界面验收。

## C2 游戏内验收

重载模组后在单人世界测试。魔法存储配置中的递归合成深度（`recursionCraftingDepth`）设为 **0**，以确保走本阶段已适配的普通路径；保留原值，验证结束后可恢复。先记下对应物品合成列，以下按增量核对。

1. 把木材与凝胶存入魔法存储，普通火把配方执行一次，合成数量增加 3；从存储取出已有火把不再增加。
2. 批量制作火把，例如实际得到 30 个，则只增加 30；连续制作或长按制作时，每次真实产出只累计一次。请求量不足一个配方产量时按实际产出量核对。
3. 使用单件配方，例如制作 2 把木剑，增加 2。也可验证一个模组物品配方，仍按产物所属模组筛选。
4. 存储中的材料只够部分目标数量时，核对实际得到多少就增加多少；材料耗尽、缺工作站、禁用材料或无法合成时不增长。
5. 仅打开、搜索、切换配方、刷新可合成数量，均不增加。不要为验证回退特意破坏世界或制造异常；材料提取回退与重复回调由隔离测试覆盖。
6. 方便时使用接近满容量的测试存储，确认成功产物（含被正常交付到角色附近的余量）只计一次；取出已有物品、补存材料不增加合成。
7. 检查生涯与当前世界增量一致；保存退出重进后保留；再通过原版界面制作一次火把，仍只增加 3。
8. C2 已由用户确认完成。多人验收使用下方 C4 清单。

若未增长，先确认单人、递归深度为 0，并查看客户端日志中的 `MagicStorage ... standard/batch crafting enabled` 或 `MagicStorage crafting disabled` 原因。验收反馈请提供物品、实际产量和统计增量。

## C3 自动化范围

在同一命令中运行的递归夹具使用真实生产采集器和模拟节点输入，经过节点产量 IL、接受迭代 IL、弱键缓存绑定及实际结算事务。节点列表代表上游已经按库存剪枝的结果，夹具不验证原模组的剪枝算法。覆盖 23 项：全量/部分/完整库存覆盖、同类型多分支、批次乘量、成功多轮和失败末轮、余量不重复、附加产物、交付回调改量改类型、预览不增长、材料回退、存储满余量、异常、多人与旧世界排除、缓存重算和数量不一致拒绝。`MAGIC_STORAGE_RECURSIVE_SCENARIOS_OK` 只表示隔离验证通过，真实配方、库存剪枝及显示仍需游戏验收。

## C3 游戏内验收

在单人世界重载模组，魔法存储递归合成深度设为足以覆盖目标配方链的正数（如 3）；根据模组配置要求刷新或重新打开合成界面。准备目标配方所需的工作站，先记录各物品合成列；以下按增量核对，具体消耗数量以游戏当前配方为准。

1. **没有中间库存**：例如存储中只有铁矿石和其他必需材料，没有铁锭，通过递归制作一件需铁锭的武器。武器增加实际产量，铁锭增加本次实际新合成的全部数量，即使已被武器消耗；矿石是已有原料，不增加合成数量。
2. **全部已有**：先提供足够的现成铁锭再制作同配方；只有本次新制作的武器增长，已有铁锭不新增合成记录。
3. **部分已有**：只提供部分所需铁锭，其余由矿石递归制作。铁锭只增加本次补制的数量。可先移走额外成品，避免其他现成材料让上游剪掉整条子链。
4. **有中间余量**：选择产物批量与下游需求不整除的链。例如当前配方为每次 3 个火把、篝火需要 5 个火把，且存储没有火把时，递归制作 1 个篝火应记录火把 +6、篝火 +1，留下的 1 个火把不再额外加一次。
5. **多层或多分支**：方便时用一件存在多层中间配方的装备/家具测试，核对每种本次新生产的中间物品；相同中间物品出现在多个分支时，应累计其全部新生产量。
6. **浏览不计产**：仅搜索、切换配方、修改目标数量或刷新列表时，各列不增长；材料不足、缺少工作站或无法合成时也不增长。请求大批量而只成功一部分时，按实际完成的链核对。
7. **持久化与回归**：生涯及当前世界均正确增长，保存退出重进后保留；关闭递归后普通/批量合成仍准确，原版界面合成也不重复。

C3 单人已由用户确认完成。多人验收使用下方 C4 清单。日志中 `recursive full-chain crafting enabled` 表示递归入口启用；若看到 `MagicStorage recursive crafting disabled`，请提供其原因。

## C4 自动化范围

同一命令另检查真实上游预编译的 SendCraftRequest、ReceiveCraftRequest 和 HandleCraftWithdrawAndDeposit 可与普通、递归采集共存，`MAGIC_STORAGE_NETWORK_HOOKS_OK` 表示新增 4 个网络 Hook 安装/释放通过。

`MAGIC_STORAGE_NETWORK_SCENARIOS_OK` 在真实生产接收事务及真实结算 IL 上运行 8 个隔离场景：匹配请求、材料回退、请求量不匹配、无有效存储早退、完成后的接收异常、存储满余量、无标记和嵌套请求隔离。玩家身份来自真实入站连接的门控需在游戏中验证，夹具不建立实际连接。

`MAGIC_STORAGE_CONFIRMATION_CHECKS_OK` 直接链接生产模型，覆盖随机会话、连续序号、请求指纹、跨运行时 ID 的稳定物品/前缀名、无材料配方、重放、错误来源确认、提前到达的确认、失败回退、异常 Abort、超时、世界与角色切换、重叠请求恢复、正文长度/截断、队列和标量预算、两个连接相同请求及竞争失败。模型不发送统计增量；数量候选只在本地完成和成功确认同时成立时释放。

运行这一命令后，可再运行存档/包检查以验证双范围及最终 .tmod，命令见 [存档检查](../DataFormatChecks/README.md)。检查器也解析中英文 HJSON，核对兼容提示键集合一致。测试不启动世界、不写人物或世界存档；真实连接时序、材料竞争和 UI 状态不由隔离测试替代。

## C4 游戏内验收

C1–C4 已全部由用户确认完成，以下保留为后续版本的多人回归清单。

主机/服务器和加入者都更新本模组并重载。先使用主机联机，两名玩家各自记录操作前的生涯/当前世界数值；有条件再在专用服务器重复关键项目。

1. **兼容提示**：两端进入世界后，在物品页悬停 `?`，应由等待服务器转为已启用成功确认；普通/批量与递归分别显示已启用。按左或右 Shift 显示全链规则及等待确认数量，松开恢复简短提示；中英文均检查。
2. **主机普通与批量**：递归深度设为 0，通过魔法存储制作一次火把应 +3；实际批量产出 30 个应 +30。只有发起者增长，加入者不增长；确认完成后等待数归零。
3. **加入者普通与批量**：交换角色重复上一项，确认归属不落到主机或其他玩家。
4. **递归全链**：两端分别把递归深度设为正数，重复 C3 的无中间库存、全部已有、部分已有和中间余量；发起者应与单人口径一致，其他人不增长。
5. **材料竞争**：同一存储只放够一份目标配方的材料，两人接近同时制作。只累计实际成功的一方；失败回退的一方整条链不增长。连续正常制作也不重复累计。
6. **非合成与失败**：浏览、刷新、取出已有物品、材料不足、缺工作站及微光分解不增加合成；方便时检查存储满但成功交付的余量只计一次。
7. **保存与重连**：确认入账后保存退出重进，记录保留；重连或换世界后重新协商，不出现旧确认补记或串世界。无需故意破坏连接制造未确认丢失；异常与超时由隔离测试覆盖。
8. **单人及原版回归**：回单人检查普通、批量和递归仍正常；多人通过原版界面合成仍只计一次。

若停在等待或未启用，记录物品页 `?` 的状态以及日志中的 MagicStorage 安装/关闭原因；不要以点击次数代替实际产量。反馈注明主机或加入者、目标配方、实际产量、已有中间材料和统计增量。确认机制不提供防作弊配方重算，也不补记跨会话未确认操作。
