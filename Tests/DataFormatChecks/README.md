# 存档与列表模型检查

先编译模组，在仓库根目录执行：

```powershell
dotnet run --project Tests/DataFormatChecks/DataFormatChecks.csproj -p:TmlPath=D:/Steam/steamapps/common/tModLoader -- D:/Steam/steamapps/common/tModLoader bin/Debug/net8.0/ComprehensiveStatistics.dll
```

加载真实生产程序集与 TagIO，以内存构造标签检查格式升级、未来格式拒绝、压缩重载、双范围和世界隔离、缺失内容、样式、稀疏字段和饱和保护。子页检查覆盖迁移不覆盖新状态、选择容错、筛选合计、精确排序、体积格式和按钮换行。钓鱼检查覆盖三个子页的固定顺序、鱼饵视图整体迁移、液体折叠迁移、选择及新状态保留、鱼竿结果与未分类历史的合计、来源筛选和鱼竿名称搜索。

合成检查覆盖独立 `items/crafts` 数量在格式 4 的双范围持久化、拾取/丢弃不串列、缺失内容保留、合成排序状态、仅合成条目、来源与搜索组合筛选、饱和合计及数值升降序；也核对本机原版三参数合成回调签名。原版回调时序、真实合成结果和 UI 绘制需按下方游戏清单验收。

可在命令末尾追加隔离 `.tmod` 路径，核对包内 DLL 和两个图标与编译结果/源文件逐字节一致。生产 UI 的图标依赖通过回调隔离，不验证真实绘制、字体、缩放或输入法；不读取用户存档。

## C1 游戏内验收

建议先记录原有数值，以下均按增量核对。重载本模组后，使用原版合成界面完成：

1. 用 1 木材与 1 凝胶制作一次普通火把，应增加 3；再制作 9 次，累计增量应为 30。鼠标已有火把时继续制作，也只增加新产出的 3。
2. 制作 2 把木剑等单件配方，数量增加 2；原有背包物品和仅浏览配方不补算合成。合成后正常放入背包，不应凭空增加拾取。
3. 丢出、拾回或从箱子取出已有物品，不改变合成数量；商店购买、旅途复制、微光也不改变。无法合成及鼠标持有不兼容物品时不增长。
4. 搜索火把，检查分组合计仅含匹配物品；点击合成表头切换降序、升序、无排序；零值淡化且只有合成记录的物品可以显示。切去弹药、击杀、经济再切回，检查无额外数值残留或列错位。
5. 检查生涯和当前世界均增加；保存退出重进后记录仍在。换第二个世界，其当前世界从自身记录开始，生涯保留总数；回原世界恢复原切片。合成排序应按生涯/世界独立保存。
6. 切换中英文并调整 UI 缩放，检查四列表头、行和合计对齐，名称不覆盖数字；合成表头悬停显示口径提示。
7. 可联机时，两名玩家分别通过原版界面合成，确认只增加自己的统计；主机与加入者都检查保存重进。
8. C1 已由用户确认完成。魔法存储后续验收使用 [专用检查清单](../MagicStorageChecks/README.md)；当前已启用单人普通与批量合成。

这些操作验证真实回调与绘制；自动化模型检查不能代替此验收。
